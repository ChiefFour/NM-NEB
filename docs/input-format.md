# The `input` file format (NM-NEB driver)

The NEB driver (`src/nmneb`) reads its setup from a plain-text file named
`input` in the working directory. The file consists of labelled blocks that
are located by keyword search (case-sensitive), so the order of the blocks
does **not** matter, and unrecognized lines are ignored.

Units: **coordinates in Ångström** (converted to bohr internally),
**energies in hartree**.

## Keywords

| Keyword | Meaning | Example |
|---|---|---|
| `Atom Number` | Number of atoms | `8` |
| `Keyword` | Gaussian route line used for single-point calculations | `#force b3lyp/6-31G* em=GD3 nosymm` |
| `geometry 1` | Reactant-side geometry: `natom` lines of `Symbol x y z` | `C 0.899644 -0.263425 0.102621` |
| `geometry 2` | Product-side geometry (see note below) | — |
| `printl` | DL-FIND print level | `4` |
| `printf` | DL-FIND frequency print level | `4` |
| `iop` | Optimization type (`3` = NEB) | `3` |
| `icoord` | Coordinate system (`100` Cartesian, `120` internal/Z-matrix) | `100` |
| `nframe` | Number of coordinate frames (`1` for NEB) | `1` |
| `Nimage` | Number of NEB images (excluding endpoints) | `8` |
| `maxcycle` | Maximum number of optimization iterations | `100` |
| `nebk` | NEB spring constant | `0.01` |
| `tolerance` | Gradient convergence threshold (a.u.) | `1.5D-3` |
| `tolerance_e` | Energy convergence threshold (a.u.) | `3.0D-5` |
| `maxstep` | Maximum step size (a.u.) | `0.5D0` |
| `scalestep` | Step-scaling factor | `1.D0` |

### Notes

1. **`geometry 1` / `geometry 2` block termination:** each geometry block is
   terminated by the next keyword. The geometry lines may be followed by an
   `end geometry N` line in the example files; the parser reads exactly
   `natom` lines per frame, so the trailing `end` line is not required.

2. **Multiple frames (`nframe > 1`):** if `nframe > 1`, `geometry 2` may
   contain several frames separated by blank lines (see `examples/nmneb/input-z`,
   which uses a `#geom of nimage` comment line before the frame block).

3. **`nmass` / `massweight`:** these lines appear in the example `input` files
   but are **not** parsed by the current `get_input.f90`. They are retained
   for compatibility with DL-FIND input decks; you may keep or delete them.

4. **Displaced endpoints:** for NM-NEB runs, `geometry 1` and `geometry 2`
   must be the improved endpoints R′ and P′ generated by
   `src/mode-displacement` (or by the mode-displacement step of the workflow).
   The linear-interpolation variant (`examples/lineb/input`) uses the raw
   minima instead.
